# 小组件示例：sysmon

演示**插件如何向主界面注入实时展示块**（CPU / 内存 / GPU）。这是
`docs/小组件设计.md` 的参考实现，也是用户实际会用的插件。

## 怎么跑

1. 把本目录复制到 `<仓库根>/plugins/sysmon`
2. 重启平台（或等 plugins 模块的目录轮询发现它）
3. 主界面顶部出现环形进度；有 N 卡时还会多一个 GPU 卡

`plugins/` 目录被 `.gitignore` 排除——那是用户自己的插件存放处，
所以示例放在 `examples/` 下，而不是直接放进去。

## 关键点

**声明写在 `kugua-plugin.json` 的 `widgets` 里**，运行时代码只管推数据：

```json
{ "id": "cpu", "type": "gauge", "title": "CPU",
  "unit": "%", "max": 100, "prominence": "primary",
  "warn": 70, "danger": 90, "stale": 15 }
```

```js
ctx.广播("widget.data", { id: "cpu", 值: 42.5 });
```

四处容易踩的坑：

1. **不要写位置。** 没有 `slot` / `order` / `size` 这些字段，
   写了也不会生效。位置和外形由平台按 `prominence` 决定，用户还能覆盖。
2. **`on_unload` 必须清掉定时器。** 否则插件卸载后还在推数据，
   界面会收到「幽灵」值。
3. **取不到的数据就别声明。** GPU 启动时探测一次 `nvidia-smi`，
   探不到就**永久放弃**并隐藏该组件。显示假的 `0%` 或永远的「无数据」
   比不显示更坏——用户分不清是「还没采到」还是「这台机器根本没法采」。
4. **配置改动订阅的是 `module.config.changed`，不是 `module.config`。**
   后者由主控 `sendEventTo(模块名)` 定向发送，只发给**注册过的模块进程**；
   插件不是独立模块，收不到。广播不带具体值，所以收到后重新 `ctx.配置()` 拉一次。

## 配置

清单里的 `配置声明` 会自动生成配置页，无需写任何前端代码。三项：

| 键 | 默认 | 说明 |
|---|---|---|
| `intervalMs` | 1500 | CPU / 内存采样间隔。下限 500ms 是硬约束 |
| `gpu` | true | 是否采集 GPU |
| `gpuIntervalMs` | 6000 | GPU 采样间隔 |

**为什么 GPU 要降到 6 秒**：`nvidia-smi` 单次约 0.2 秒，每 1.5 秒起一个子进程
既费电，又容易被杀软盯上（频繁起子进程是典型的可疑行为特征）。
GPU 使用率本来就是慢变量，6 秒完全够。

**为什么间隔要夹下限**：用户填 `1` 会得到 1ms 定时器，把 CPU 直接吃满。
`读选项()` 把非法值全部夹回 `[500, 10000]`。

## 关于 `prominence`

- `primary` → 大卡，放顶部（单插件最多 2 个，多了自动降级）
- `normal` → 横条
- `secondary` → 压进底部状态栏

它表达的是**相对重要性，不是位置**：插件可能跑在完全不同的前端上，
无从知道「顶部」在哪、屏幕多宽。
