# 小组件示例：netspeed

实时上下行速率。和 `../widget-demo`（sysmon）相比，这个插件的重点不在"怎么推数据"，
而在 **"数据源很贵时怎么办"**。

## 怎么跑

1. 把本目录复制到 `<仓库根>/plugins/netspeed`
2. 重启平台
3. 到配置页把「启用网络速率监控」打开，再重启插件

**默认是关闭的**，开启前不会声明任何组件、也不会起子进程。

## 为什么默认关闭

实测（Windows 11 / PowerShell 5.1）读取网卡累计字节的耗时：

| 方式 | 首轮 | 之后每轮 |
|---|---|---|
| 每次都起新进程 | ~1.4 秒 | ~1.4 秒 |
| **常驻进程，脚本内循环** | ~1.4 秒（只启动一次） | **~0.9 秒** |

1.4 秒里绝大部分是 PowerShell 自身启动。所以这里常驻一个子进程，由它自己
循环输出，主进程只解析。代价是多一个约 60-80MB 的常驻进程——对"顺便看看网速"
来说太贵了，因此做成显式开启。

## 清单里为什么没有 `widgets`

两个组件是 `on_load` 里确认「确实启用了」之后**运行时补声明**的。

踩过这个坑：清单里的 `widgets` 是**静态声明**，平台不管插件有没有启用都会注册。
于是默认关闭的 netspeed 照样在主界面留下「下行 —」「上行 —」两个卡片——
正好是设计稿反复强调要避免的「永远无数据的卡片」。

区别在这里：

| | 静态声明（清单 `widgets`） | 运行时补声明（`ctx.声明小组件`） |
|---|---|---|
| 时机 | 加载插件时就注册 | `on_load` 里按实际能力决定 |
| 适合 | 一定能提供的组件（CPU、内存） | 能力不确定的（GPU、需要开关的网速） |

## 四个容易踩的坑

**一、虚拟网卡会让速率翻倍。**

本机同时有 `WLAN`（物理）和 `Mihomo`（Meta Tunnel，代理虚拟网卡），
两者字节数相近——因为**代理的流量本身就走 WLAN**。全累加就是同一份流量算两遍。

所以默认按网卡描述过滤掉 `Virtual|Tunnel|Hyper-V|VMware|Loopback|Pseudo|Bluetooth`，
并按 `InterfaceType -ne 53`（隧道）排除。确实想统计全部网卡时把
`includeVirtual` 打开。

**二、`on_unload` 必须 kill 子进程。**

忘了这一步的后果很隐蔽：插件卸载了，PowerShell 还在每 0.9 秒醒一次、永远不退。
界面上看不出任何异常，只有任务管理器里能发现。

这类"泄漏"单测很难覆盖，所以用真实验证：`on_load` 后数常驻 PowerShell 进程数，
`on_unload` 后再数一次，必须回落。

**三、计数器会回退。**

网卡重置、拔插网线、休眠恢复都会让累计字节变小。此时 `这次 - 上次` 是大负数：

- 显示负速率显然不对
- 当成 0 也不对（会显示"没流量"，但实际是数据源断了）

正确做法是**丢掉这一轮、重新建立基线**。见 `处理一行()` 里的回退判断。


**四、网卡会拔插，而「加总后记一个数」应付不了。**

最初把**所有网卡加总**后记一个基线，两种情况下都会给出错误数字：

| 情况 | 表现 |
|---|---|
| 拔掉一块网卡 | 总量骤降 → 差值为负 → 该轮被丢弃（界面看起来像卡住） |
| 插上一块新网卡 | 它的历史累计字节一次性算进差值 → 速率瞬间冲到几万 KB/s |

现在**按网卡名分别记基线**，PowerShell 侧每轮**重新扫描**网卡集合：

- 新网卡第一次出现只记基线，不出数
- 拔掉的网卡在轮末清掉（否则同名网卡重新插上会拿到过期基线，
  时间差可能是几小时，算出的速率趋近 0，界面表现为"网速突然很慢"）
- 计数器回退仍按上面的规则丢轮重建

## 多块物理网卡并存时取最快的，不累加

这是刻意的选择。加总看着更"全面"，实际有两个问题：

1. 有线 + Wi-Fi 同时 `Up` 时，同一份流量可能走两条路（尤其开了代理），
   加总直接翻倍——正是上面第一条坑要避免的重复计数，加总等于把它绕回来
2. 用户看「网络速率」想知道的是「现在网快不快」，不是「所有网卡一共搬了
   多少字节」。后者在有闲置网卡时是个只增不减的误导数字

取最大值天然满足"不重复计数"：同一份流量无论如何只会在一条路上跑。

代价：如果同时用两条链路做负载均衡，显示的是较快那条而非总吞吐。
这种场景少见，而且用户想看的通常也是"能跑多快"。


## 为什么不做"主动测速"

设计稿说「测速（主动）与实时速率（被动）分开」。这里**只做被动**：

主动测速要往公网传大量数据——可能跑满用户的带宽（按流量计费时是真金白银），
也会暴露"这台机器在跑测速"。它该是独立功能、独立开关、明确告知，
混在实时监控里会让用户莫名其妙被占满带宽。

## 为什么只在 Windows 上声明组件

Linux 读 `/proc/net/dev`、macOS 用 `netstat -ib` 都能拿到字节计数，但没在这些
平台验证过。没验证过的代码不如不写——非 Windows 上直接不声明组件，
用户看到的是"没有这个功能"，而不是"有个卡片永远空白"。
