# 苦瓜工作室 开发细则

> 本文定义技术选型、协议、目录、编码规范与测试方法。
> 顶层蓝图见《架构设计.md》，知识库见《知识库设计.md》，互操作见《互操作设计.md》，施工任务见《改造清单.md》。

## 一、技术选型

| 层面 | 选型 | 说明 |
| --- | --- | --- |
| 语言/运行时 | Node.js LTS + TypeScript（ESM，NodeNext） | 主控与内置模块 |
| 仓库 | npm workspaces 单仓库（monorepo） | 统一构建、统一测试 |
| 通信传输 | WebSocket（`ws`），JSON 文本帧，仅监听回环地址 | 模块间统一走总线 |
| 持久化 | SQLite：mkg 用 better-sqlite3；主控审计用内置 `node:sqlite`（避开原生模块与 spawn 冲突） | 单文件、零运维、支持 FTS5 |
| 标签持久化 | 侧车 `.mkg.json`（文件旁） | 可随文件迁移，DB 为缓存 |
| GUI | 本地 Web UI（`@kugua/webui`）：HTTP + WebSocket，浏览器访问 | 便于插件扩展页面，无 Electron 依赖 |
| 脚本/外部程序 | 子进程 + stdio（JSON Lines / MCP） | 跨语言、跨项目 |
| 互操作 | MCP（JSON-RPC 2.0，stdio 优先） | 暴露与被接入 |
| 测试 | Vitest | 不依赖外网 |
| 常驻 | Windows 服务（WinSW/NSSM）或登录任务 | 见架构设计第九节 |

> 说明：功能模块的实现语言不设限；确定性工具优先 Node 内置与轻依赖实现。

## 二、总体架构

- **星型拓扑**：主控 `@kugua/main` 是唯一 WebSocket 服务端，所有模块作为客户端接入；模块间不直连。
- **进程模型**：每个模块独立进程，崩溃不影响主控与其他模块。
- **能力注册表**：模块在握手时声明能力；入口统一由注册表派生（指令/GUI/定时/开机/外部）。
- **认证**：可选令牌；模块握手须与主控配置一致。
- **权限**：模块与能力两级声明，取交集；危险能力默认不外露。

## 三、苦音协议（Nigane）

### 3.1 传输
WebSocket，JSON 文本帧，UTF-8；主控默认监听 `ws://127.0.0.1:24601`（可配置）。

### 3.2 信封

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `nigane` | string | 是 | 协议版本，当前 `"0.2"` |
| `id` | string | 是 | 消息唯一标识 |
| `type` | string | 是 | `hello` / `hello_ack` / `request` / `response` / `event` / `error` / `ping` / `pong` |
| `from` | string | 是 | 发送方模块名 |
| `to` | string | 否 | 目标模块；`event` 广播时省略 |
| `action` | string | 否 | 动作名（`request`/`event` 必填） |
| `params` | any | 否 | 请求/事件参数 |
| `data` | any | 否 | 响应数据 |
| `code` | number | 否 | 错误码（`error` 必填） |
| `message` | string | 否 | 错误描述 |
| `echo` | string | 否 | 对应请求 `id` |
| `time` | number | 是 | 秒级 Unix 时间戳 |

### 3.3 握手

1. 模块连接后 5 秒内发送 `hello`，`params = { name, version, capabilities, capabilityDefs?, permissions?, token? }`。
2. 主控校验令牌：一致则回 `hello_ack` 并登记；不一致回 `error`（1001）并断开。
3. 模块名唯一，重复注册拒绝后者。
4. `capabilityDefs` 为能力声明数组（见《架构设计.md》4.2），主控汇总为全局注册表。

### 3.4 路由

- `request`：按 `to` 转发；目标不存在回 `error`（1002）。
- `response` / `error`：按 `to` 转发回请求方，按 `echo` 匹配挂起请求。
- `event`：广播给除发送方外的所有已注册模块。
- `ping`：主控直接回 `pong`。

### 3.5 命名约定

- 动作名统一 `模块.动作`（如 `image.gifUnzip`、`mkg.search`）。
- 能力动作即 `模块.动作`，缺省与能力名一致。
- 主控内置能力动作：`capability.list` / `capability.get` / `capability.call` / `capability.command`。
- 长任务使用统一动作名 `job.*`（`job.start/status/cancel/list`）与事件 `job.log` / `job.done`；不新增信封类型。

### 3.6 错误码

| 码 | 含义 |
| --- | --- |
| 1001 | 认证失败 |
| 1002 | 目标模块不存在 |
| 1003 | 未注册即发送业务消息 |
| 1004 | 消息格式非法 |
| 1005 | 请求超时 |
| 1006 | 权限不足 |
| 2000+ | 模块自定义业务错误 |

### 3.7 扩展规则

- 只增加可选字段，不改变既有字段语义；
- 协议版本变更时升级 `nigane` 字段，主控保留旧版本兼容窗口。

## 数据布局

分两类，不混放：

1. **模块只读静态资源**（语料/模型/字体等）：放在各模块的 `packages/modules/<模块>/assets/`，
   用 `@kugua/paths` 的 `模块资源(import.meta.url, "...")` 解析，**与 cwd 无关**（模块自包含、可整体拷贝）。
   大文件（如 22MB 的 `model1.txt`）不入版本库，用脚本从 `RunningData` 拷入。
2. **平台运行时可变数据**（db / 日志 / 作业 / 调度 / 资料目录）：放在**可配置数据根**
   （默认 `<cwd>/data`，`KUGUA_DATA_DIR` 可覆盖），用 `@kugua/paths` 的 `运行数据("...")` 解析。

```
packages/modules/<模块>/
  src/
  assets/        # 仅只读资源（随模块走）
  dist/
data/            # 仅运行时可变数据（不随代码走）
  mkg.db  audit.db  logs/  jobs/  library/  scheduler/
```

规则：代码不得硬编码 `data/generators` 这类共享路径；资源一律经 `@kugua/paths` 解析。

## 六、测试方法

1. **单元测试**：能力声明与 Schema 转换、协议信封、侧车读写、查询构造。
2. **集成测试**：进程内启动主控 + 两个客户端，覆盖握手/声明/请求/广播/权限。
3. 合入前 `npm run build` 必须通过；测试一律使用 `127.0.0.1` 与独立端口，禁止依赖外网。
4. 历史测试脚本已清理；新测试随新代码同步编写。

## 七、编码与版本规范

1. TypeScript strict；公共 API 必须有类型标注。
2. 注释使用中文，标识符使用英文（历史中文 API 可保留，但新增能力名用英文 `模块.动作`）。
3. 提交信息：`<类型>: <说明>`（新增/修复/重构/文档/测试/清理）。
4. 每次功能变更同步更新《更新日志.md》，遵循语义化版本。
5. 资源约束：空闲时不得有周期性磁盘写；日志内存环形缓冲 + 限流落盘；检索优先索引。
6. 权限显式声明，危险能力默认不暴露。
