# 苦瓜工作室（KuguaStudio）开发细则

> 本文档依据《开发计划.txt》第三节第 1 条要求制定，明确整体技术选型、项目架构、实施步骤与测试方法。
> 开发过程中须随时更新本文档与《更新日志.md》。

## 一、技术选型

| 层面 | 选型 | 说明 |
| --- | --- | --- |
| 主控与通信层 | Node.js LTS + TypeScript（ESM，NodeNext） | 单仓库多进程，模块以独立进程运行 |
| 通信传输 | WebSocket（`ws` 库），JSON 文本帧 | 仅监听 127.0.0.1，本地进程间通信 |
| 公用库 SDK | `@kugua/nigane`（TypeScript 先行） | 各模块引用同一 SDK 实现苦音协议 |
| Python 模块 | Python 3.12，经 CLI/子进程或后续 Python 版 SDK 接入 | AI、图像处理等模块后期接入 |
| 本地 GUI | Electron（已落地，里程碑 M5） | 帧内知识库浏览 + 聊天侧栏 + 插件/设置视图 |
| 测试 | Vitest（单元 + 集成测试） | 测试不依赖外部网络 |
| 包管理 | npm workspaces 单仓库（monorepo） | 统一构建、统一测试 |
| 持久化（MKG） | SQLite（better-sqlite3）+ 宿主文件系统索引 | 里程碑 M3 已实施 |

## 二、总体架构

- **星型拓扑**：主控进程 `kugua-main` 维护唯一 WebSocket 服务端，所有模块（Napcat 接入、GUI、AI、小游戏等）作为客户端接入，模块间通信一律经主控路由，禁止模块间直连，以降低耦合。
- **进程模型**：每个模块是独立的操作系统进程，由用户或主控启动；模块崩溃不影响主控与其他模块。
- **认证**：模块握手时须携带令牌（token），与主控配置一致方可注册。
- **Napcat 兼容**：苦音协议的 request/response/echo 语义对齐 OneBot 11（Napcat）的 action/params/echo 结构，便于 Napcat 适配层直接转发。

## 三、苦音协议（Nigane）v0.1 规范

### 3.1 传输
- WebSocket，JSON 文本帧，UTF-8。
- 主控默认监听 `ws://127.0.0.1:24601`（可配置）。

### 3.2 信封（Envelope）
所有消息统一为如下 JSON 对象：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `nigane` | string | 是 | 协议版本，当前为 `"0.1"` |
| `id` | string | 是 | 消息唯一标识（UUID） |
| `type` | string | 是 | `hello` / `hello_ack` / `request` / `response` / `event` / `error` / `ping` / `pong` |
| `from` | string | 是 | 发送方模块名 |
| `to` | string | 否 | 目标模块名；`event` 广播时省略 |
| `action` | string | 否 | 动作名（`request`/`event` 必填） |
| `params` | any | 否 | 请求/事件参数 |
| `data` | any | 否 | 响应数据 |
| `code` | number | 否 | 错误码（`error` 时必填） |
| `message` | string | 否 | 错误描述 |
| `echo` | string | 否 | 响应对应的请求 `id`（对齐 OneBot 语义） |
| `time` | number | 是 | 秒级 Unix 时间戳 |

### 3.3 握手
1. 模块建立连接后 5 秒内发送 `hello`，`params` 携带 `{ name, version, capabilities, token }`。
2. 主控校验 token：一致则回复 `hello_ack` 并登记模块；不一致回复 `error`（code 1001）并断开。
3. 模块名须唯一，重复注册时主控拒绝后注册者。

### 3.4 路由
- `request`：主控按 `to` 转发；目标不存在时向发送方回 `error`（code 1002）。
- `response` / `error`：按 `to` 转发回请求方，请求方按 `echo` 匹配挂起的请求。
- `event`：主控广播给除发送方外的所有已注册模块。
- `ping`：主控直接回 `pong`（心跳保活）。

### 3.5 错误码
| 码 | 含义 |
| --- | --- |
| 1001 | 认证失败 |
| 1002 | 目标模块不存在 |
| 1003 | 未注册即发送业务消息 |
| 1004 | 消息格式非法 |
| 1005 | 请求超时 |
| 2000+ | 模块自定义业务错误 |

### 3.6 扩展规则
- 新增字段不得破坏既有字段语义；信封可安全添加可选字段。
- 协议版本号变更时 `nigane` 字段升级，主控保留旧版本兼容窗口。

## 六、测试方法

1. **单元测试**：SDK 信封构造、编解码、错误分支。
2. **集成测试**：进程内启动主控 + 两个客户端，覆盖握手认证、request/response、未知目标、事件广播、心跳。
3. 每个里程碑合入前 `npm run build && npm test` 必须全绿。
4. 测试一律使用 `127.0.0.1` 与独立端口，禁止依赖外网。

## 七、编码与版本规范

1. TypeScript strict 模式；公共 API 必须有类型标注。
2. 注释使用中文；标识符使用英文。
3. 提交信息格式：`<类型>: <说明>`（类型：新增/修复/重构/文档/测试）。
4. 每次功能变更须更新《更新日志.md》，遵循语义化版本。
5. 资源约束落实：主控空闲时不得有周期性磁盘写；日志采用内存环形缓冲 + 落盘限流；检索类功能优先内存索引。
