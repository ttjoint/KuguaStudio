# 苦音接入协议（Nigane Protocol）

面向**外部程序**：任何语言、任何进程，只要能用 WebSocket 收发 JSON，就能接入苦瓜工作室，
成为平台的一个功能模块，与平台双向通信，并把自身能力暴露到平台的指令面板 / AI 路由 / GUI。

协议实现参考：`packages/nigane/src/index.ts`（TypeScript，Node 侧）。
协议版本常量：`0.2`（`packages/nigane/src/index.ts` 的 `协议版本`）。

---

## 一、连接

| 项 | 值 |
|---|---|
| 地址 | `ws://<主控host>:<主控port>`，默认 `ws://127.0.0.1:24601` |
| 端口来源 | `kugua.config.json` 的 `port`，或环境变量 `KUGUA_PORT` |
| 传输 | 标准 WebSocket 文本帧，每帧一个 JSON 对象 |
| 认证 | 握手 `params.token`；主控配置了 `token` 时必须一致，否则关闭连接 |

单一实例保证由平台的**全局锁**负责，与接入方无关：同一时刻只可能有一个平台在监听，
所以外部程序不存在「连到错误的平台」的问题。

---

## 二、信封格式

所有消息都是同一个信封结构：

```json
{
  "nigane": "0.2",
  "id": "3f2b…uuid",
  "type": "request",
  "from": "my-tool",
  "to": "kugua-main",
  "action": "mkg.note.create",
  "params": { "title": "标题" },
  "data": null,
  "code": 0,
  "message": "",
  "echo": null,
  "time": 1760000000
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `nigane` | ✅ | 协议版本字符串 |
| `id` | ✅ | 本消息唯一 id（UUID） |
| `type` | ✅ | `hello` / `hello_ack` / `request` / `response` / `event` / `error` / `ping` / `pong` |
| `from` | ✅ | 发送者模块名 |
| `to` | 视类型 | 目标模块名；内置目标为 `kugua-main` |
| `action` | 视类型 | 动作名，`request` / `event` 必填 |
| `params` | 视类型 | 请求参数 / 事件负载 |
| `data` | 视类型 | 响应数据 |
| `code` | `error` | 错误码 |
| `message` | `error` | 错误说明 |
| `echo` | `response`/`error` | 被回应消息的 `id`（用于配对） |
| `time` | ✅ | Unix 秒级时间戳 |

### 错误码

| 码 | 含义 |
|---|---|
| `1001` | 认证失败 |
| `1002` | 目标不存在 |
| `1003` | 未注册（请求的动作没人提供） |
| `1004` | 格式非法 |
| `1005` | 请求超时 |
| `2000` | 处理器内部异常（`message` 为异常文本） |

## 三、握手

连接建立后，**必须先发 `hello`**，否则主控在超时后以 `1002` 关闭连接。

```json
{
  "nigane": "0.2",
  "id": "…",
  "type": "hello",
  "from": "my-tool",
  "time": 1760000000,
  "params": {
    "name": "my-tool",
    "version": "0.1.0",
    "capabilityDefs": []
  }
}
```

`params`：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 模块名，全局唯一 |
| `version` | | 版本号 |
| `token` | | 主控配置了 token 时必填 |
| `capabilities` | | 能力名列表；**省略时**由 `capabilityDefs` + 已注册处理器自动派生 |
| `capabilityDefs` | | 能力声明数组，见第五节 |

成功响应：

```json
{
  "type": "hello_ack",
  "from": "kugua-main",
  "to": "my-tool",
  "echo": "<hello 的 id>",
  "data": { "modules": ["webui", "food", "mkg", "my-tool"] }
}
```

握手失败：主控回 `error` 后关闭连接（`4001` 关闭码 = 认证失败，`4003` = 缺模块名）。

**顶号语义**：同名模块重新连接时，主控会关闭旧连接并以新连接替换，
旧连接对应的能力会被移除、随后由新连接重新登记。因此重启外部程序无需手动清理。

## 四、双向通信

### 4.1 外部程序 → 平台（调用平台能力）

```json
{
  "nigane": "0.2",
  "id": "req-1",
  "type": "request",
  "from": "my-tool",
  "to": "kugua-main",
  "action": "mkg.note.create",
  "time": 1760000000,
  "params": { "title": "从外部写入的笔记", "content": "正文" }
}
```

平台回：

```json
{ "type": "response", "from": "kugua-main", "to": "my-tool", "echo": "req-1", "data": { "id": "…" } }
```

失败回 `type: "error"` 带 `code` / `message`。

> 也可以把 `to` 填成另一个模块名，让平台**直接转发**给那个模块——
> 主控只做路由，不关心里面是什么。

内置动作（`to = "kugua-main"`）：

| action | 返回 |
|---|---|
| `nigane.modules.list` | 全部模块详情数组 |
| `nigane.modules.names` | 模块名数组 |

### 4.2 平台 → 外部程序（平台调用你）

你在握手时声明了 `capabilityDefs`，平台（GUI、AI 路由、指令、其它模块）
就会用这个 `action` 来调你：

```json
{
  "type": "request",
  "from": "webui",
  "to": "my-tool",
  "action": "my-tool.echo",
  "echo": "…",
  "params": { "text": "你好" }
}
```

你按同样的信封回 `response` / `error`，`echo` 填收到的 `id`。

### 4.3 只广播的事件

`type: "event"` 会广播给**除发送者外的所有在线模块**，没有响应：

```json
{ "type": "event", "from": "my-tool", "action": "my-tool.tick", "params": { "n": 1 } }
```

你也可以订阅平台的广播，例如：

| action | 何时 |
|---|---|
| `capability.changed` | 能力注册表变化（`{ 模块, 数量 }`） |
| `registry.changed` | 模块上下线 |
| `plugins.changed` | 插件目录变化 |
| `system.shutdown` | **平台即将退出**（见第六节） |

### 4.4 心跳

发送 `{"type":"ping","id":"…","from":"my-tool"}` → 平台回 `pong`（`echo` 为 ping 的 id）。
建议 30 秒一次。

## 五、能力声明

`capabilityDefs` 是你这个模块「能做什么」的清单，决定平台如何暴露你：

```json
{
  "name": "my-tool",
  "version": "0.1.0",
  "capabilityDefs": [
    {
      "名称": "my-tool.echo",
      "模块": "my-tool",
      "动作": "my-tool.echo",
      "标题": "回声",
      "说明": "把输入原样返回",
      "中文指令": ["回声"],
      "参数": { "type": "object", "properties": { "text": { "type": "string" } } },
      "暴露": { "指令": true, "GUI": true }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `名称` | 全局唯一，建议 `模块.动作` |
| `模块` | 提供者模块名（你） |
| `动作` | 苦音 `action`；缺省等于 `名称` |
| `标题` / `说明` | 人类可读文案 |
| `中文指令` | 中文别名，命中即调用；**出现在指令面板 / 可被 AI 路由** |
| `参数` | 参数 JSON Schema（object） |
| `返回` | 返回 JSON Schema（可选） |
| `危险` | 危险能力，默认不对外暴露 |
| `长任务` | 走 Job 语义（进度、取消） |
| `暴露` | 各入口开关：`指令` / `GUI` / `HTTP` 等 |

**你不需要手写能力名列表**：省略 `capabilities` 时，平台会从
`capabilityDefs` 的 `动作 ?? 名称` 加上你实际注册的处理器自动派生。

## 六、生命周期（重要）

平台区分两类外部程序，**退出行为完全不同**：

### 6.1 平台托管的模块（配置在 `kugua.config.json` 的 `modules[]`）

平台**负责其生死**：
- 启动时由主控 `spawn`
- 崩溃按策略重启
- **平台退出 / 重启时同步关闭**（先 `SIGTERM`，2 秒未退则强制 kill）

### 6.2 运行中接入的外部程序（本协议的主要场景）

平台**不负责其生死**，只做通知：
- 平台退出时广播 `system.shutdown`：

```json
{ "type": "event", "from": "kugua-main", "action": "system.shutdown", "params": { "time": 1760000000 } }
```

- **收到后由你自己决定**是否退出。你可以：
  - 直接退出；
  - 继续运行（下次平台起来再重连）；
  - 做收尾工作后再退出。
- 平台不会对你的进程发送任何信号，也不会强杀。

### 6.3 断开与重连

- 你的连接断开 → 平台立刻移除你的能力，广播 `capability.changed`，
  UI 自动刷新，指令面板不再显示你的指令。
- 重连后重新 `hello` 即恢复。**同名顶号**处理见第三节。
- 建议外部程序实现**指数退避重连**（1s → 2s → 4s → … 上限 30s）。

## 七、最小可运行示例

仓库内 `examples/external-module/` 提供了一个纯 Node 实现（不依赖本仓库任何包），
可用来对照验证协议：

```bash
node examples/external-module/run.mjs
```

它演示了：连接 → 握手 → 声明能力（`回声` 指令）→ 被平台调用 → 响应 →
订阅 `system.shutdown` 并在收到后自行退出。

## 八、非 Node 语言实现清单

用任何语言复刻时，只需要：

1. 一个 WebSocket 客户端库；
2. JSON 序列化；
3. UUID 生成（或任意唯一字符串）；
4. 维护「发出请求的 `id` → 等待中的回调」映射，靠 `echo` 配对；
5. 维护「收到的 `action` → 处理器」映射；
6. 握手后发送 `hello`，处理 `hello_ack`；
7. 订阅 `system.shutdown`，按 6.2 自行决定退出。

无二进制帧、无压缩、无自定义分帧——只有 JSON over WebSocket。
