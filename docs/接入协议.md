# 苦音接入协议（Nigane Protocol）

面向**外部程序**：任何语言、任何进程，只要能用 WebSocket 收发 JSON，就能接入苦瓜工作室，
成为平台的一个功能模块，与平台双向通信，并把自身能力暴露到平台的指令面板 / AI 路由 / GUI。

协议实现参考：`packages/nigane/src/index.ts`（TypeScript，Node 侧）。
协议版本常量：`0.2`（`packages/nigane/src/index.ts` 的 `协议版本`）。

---

## 一、连接

| 项 | 值 |
|---|---|
| 地址 | `ws://<主控host>:<主控port>`，默认 `ws://127.0.0.1:24601` |
| 端口来源 | `kugua.config.json` 的 `port`，或环境变量 `KUGUA_PORT` |
| 传输 | 标准 WebSocket 文本帧，每帧一个 JSON 对象 |
| 认证 | 握手 `params.token`；主控配置了 `token` 时必须一致，否则关闭连接 |

单一实例保证由平台的**全局锁**负责，与接入方无关：同一时刻只可能有一个平台在监听，
所以外部程序不存在「连到错误的平台」的问题。

---

## 二、信封格式

所有消息都是同一个信封结构：

```json
{
  "nigane": "0.2",
  "id": "3f2b…uuid",
  "type": "request",
  "from": "my-tool",
  "to": "kugua-main",
  "action": "mkg.note.create",
  "params": { "title": "标题" },
  "data": null,
  "code": 0,
  "message": "",
  "echo": null,
  "time": 1760000000
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `nigane` | ✅ | 协议版本字符串 |
| `id` | ✅ | 本消息唯一 id（UUID） |
| `type` | ✅ | `hello` / `hello_ack` / `request` / `response` / `event` / `error` / `ping` / `pong` |
| `from` | ✅ | 发送者模块名 |
| `to` | 视类型 | 目标模块名；内置目标为 `kugua-main` |
| `action` | 视类型 | 动作名，`request` / `event` 必填 |
| `params` | 视类型 | 请求参数 / 事件负载 |
| `data` | 视类型 | 响应数据 |
| `code` | `error` | 错误码 |
| `message` | `error` | 错误说明 |
| `echo` | `response`/`error` | 被回应消息的 `id`（用于配对） |
| `time` | ✅ | Unix 秒级时间戳 |

### 错误码

| 码 | 含义 |
|---|---|
| `1001` | 认证失败 |
| `1002` | 目标不存在 |
| `1003` | 未注册（请求的动作没人提供） |
| `1004` | 格式非法 |
| `1005` | 请求超时 |
| `2000` | 处理器内部异常（`message` 为异常文本） |

## 三、握手

连接建立后，**必须先发 `hello`**，否则主控在超时后以 `1002` 关闭连接。

```json
{
  "nigane": "0.2",
  "id": "…",
  "type": "hello",
  "from": "my-tool",
  "time": 1760000000,
  "params": {
    "name": "my-tool",
    "version": "0.1.0",
    "path": "D:\\my-tool\\main.py",
    "capabilityDefs": []
  }
}
```

`params`：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 模块名，全局唯一（身份主键，冲突按模块名判） |
| `version` | | 版本号；用于判定升级 / 回退 |
| `path` | | 模块本体物理路径；用于判定「原位」。**强烈建议上报**，否则无法区分同模块换目录 |
| `instance` | | 实例标识（可选）；同机多开时用于区分 |
| `token` | | 主控配置了 token 时必填 |
| `capabilities` | | 能力名列表；**省略时**由 `capabilityDefs` + 已注册处理器自动派生 |
| `capabilityDefs` | | 能力声明数组，见第五节 |
| `托管` | | 托管申请（可选），见第六节；仅作首次注册初始值 |

### 3.0 身份与版本门禁（重要）

平台在完成注册**之前**校验每一次接入，不符合者被拒绝（不会进入注册表）：

| 情形 | 平台反应 |
|---|---|
| 首次注册（无同名记录） | 放行，并记录版本与能力指纹 |
| 原位 + 版本更新 + `autoUpdate` 开 | **自动接受**（内置模块强制自动更新） |
| 原位 + 版本更新 + `autoUpdate` 关 | 放行，并提示「有新版本」，管理界面出现绿色「更新」按钮 |
| 原位 + 版本相同 + 能力声明变了 | **暂下线**、状态灯标红、报 `error`；需手动点「替换」 |
| 原位 + 版本回退 | **暂下线**、状态灯标红、报 `error`；需手动点「替换」 |
| 非原位（同名换路径） | **拒绝**（`warning`）；只能先移除旧注册 |
| 同路径不同名 | **拒绝**（`warning`，重复注册保护） |
| 未实现 `module.query` | **拒绝**；无法校验身份与版本 |

「原位」判定优先使用模块自报的 `path`，而非托管启动的 `entry`
（例如托管入口是 `python.exe`，而模块本体是 `main.py`）。

### 3.1 必需协议动作：`module.query`

平台通过向模块发 `module.query` 获取其当前身份。**每个模块都必须实现它**，
否则平台无法校验版本与路径，下次接入时会被拒绝并标为离线。

请求（平台 → 模块）：

```json
{ "type": "request", "from": "kugua-main", "to": "my-tool", "action": "module.query", "params": {} }
```

应答（模块 → 平台）：

```json
{
  "type": "response",
  "to": "kugua-main",
  "echo": "<请求 id>",
  "data": {
    "name": "my-tool",
    "version": "0.1.0",
    "path": "D:\\my-tool\\main.py",
    "capabilityDefs": [ /* 同握手 */ ]
  }
}
```

平台在模块首次上线后自动探测一次 ``module.query``，结果持久化到配置的
``queryable`` 字段；SDK 已默认注册该动作，无需业务代码处理。

### 3.1 托管申请（`托管`）

外部程序可在握手中自报「下次跟随平台一起启动」，由平台写入配置：

```json
{
  "name": "my-tool",
  "托管": {
    "enabled": true,
    "entry": "C:\\Python312\\python.exe",
    "args": ["D:\\my-tool\\main.py", "--hosted"],
    "cwd": "D:\\my-tool",
    "description": "我的外部工具"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `enabled` | ✅ | `true` = 随平台启动（托管）；`false` = 仅手动启动 |
| `entry` |  | 物理路径：可执行文件（`.exe`）或脚本（`.py` / `.js` …） |
| `args` |  | 附加参数；工作目录 `cwd` 缺省为主控进程的 cwd |
| `cwd` |  | 工作目录（可选） |

启动命令根据 `entry` 自动推断：`.js/.mjs/.cjs` 用 Node，`.py` 用 Python
（可用环境变量 `KUGUA_PYTHON` 指定解释器），其余直接执行。

托管启动时，子进程环境变量会额外注入：

| 变量 | 说明 |
|---|---|
| `KUGUA_URL` | 主控 WebSocket 地址 |
| `KUGUA_PORT` | 主控端口 |
| `KUGUA_TOKEN` | 认证令牌 |
| `KUGUA_HOSTED` | 固定为 `1`，标识「由平台拉起」 |

（Node 模块沿用旧约定：ws 地址与 token 作为第 1、2 个位置参数传入。）

**冲突与覆盖规则（重要）**

冲突键采用**模块名**（协议层已保证全局唯一）。

| 场景 | 行为 |
|---|---|
| 模块名不存在 | 按上报信息新建配置项并写入 `kugua.config.json`，主控日志：`托管注册：新建模块「X」` |
| 模块名已存在且一致 | 不做变更，日志：`已有配置且与上报一致` |
| 模块名已存在但有差异 | **保留已存配置**（用户在管理界面改过的值优先），仅记差异日志并向双方广播 `registry.conflict` |
| 不同模块名指向同一 `entry` | 两者都保留，记警告日志 + 广播 `registry.conflict`（需人工确认） |
| 申请托管但未给 `entry` | 不写入，日志提示需在管理界面手动配置 |

也就是说：**外部程序只能在首次注册时决定初始值，之后的配置以用户为准**。
因此每次重启外部程序都不会覆盖用户在工作室管理界面里的修改。

---

成功响应：

```json
{
  "type": "hello_ack",
  "from": "kugua-main",
  "to": "my-tool",
  "echo": "<hello 的 id>",
  "data": { "modules": ["webui", "food", "mkg", "my-tool"] }
}
```

握手失败：主控回 `error` 后关闭连接（`4001` 关闭码 = 认证失败，`4003` = 缺模块名）。

**顶号语义**：同名模块重新连接时，主控会关闭旧连接并以新连接替换，
旧连接对应的能力会被移除、随后由新连接重新登记。因此重启外部程序无需手动清理。

## 四、双向通信

### 4.1 外部程序 → 平台（调用平台能力）

```json
{
  "nigane": "0.2",
  "id": "req-1",
  "type": "request",
  "from": "my-tool",
  "to": "kugua-main",
  "action": "mkg.note.create",
  "time": 1760000000,
  "params": { "title": "从外部写入的笔记", "content": "正文" }
}
```

平台回：

```json
{ "type": "response", "from": "kugua-main", "to": "my-tool", "echo": "req-1", "data": { "id": "…" } }
```

失败回 `type: "error"` 带 `code` / `message`。

> 也可以把 `to` 填成另一个模块名，让平台**直接转发**给那个模块——
> 主控只做路由，不关心里面是什么。

内置动作（`to = "kugua-main"`）：

| action | 返回 |
|---|---|
| `nigane.modules.list` | 全部模块详情数组 |
| `nigane.modules.names` | 模块名数组 |

### 4.2 平台 → 外部程序（平台调用你）

你在握手时声明了 `capabilityDefs`，平台（GUI、AI 路由、指令、其它模块）
就会用这个 `action` 来调你：

```json
{
  "type": "request",
  "from": "webui",
  "to": "my-tool",
  "action": "my-tool.echo",
  "echo": "…",
  "params": { "text": "你好" }
}
```

你按同样的信封回 `response` / `error`，`echo` 填收到的 `id`。

### 4.3 只广播的事件

`type: "event"` 会广播给**除发送者外的所有在线模块**，没有响应：

```json
{ "type": "event", "from": "my-tool", "action": "my-tool.tick", "params": { "n": 1 } }
```

你也可以订阅平台的广播，例如：

| action | 何时 |
|---|---|
| `capability.changed` | 能力注册表变化（`{ 模块, 数量 }`） |
| `registry.changed` | 模块上下线 |
| `plugins.changed` | 插件目录变化 |
| `system.startup` | **平台已就绪**（`{ 版本, 协议, 启动时间 }`） |
| `system.shutdown` | **平台即将退出**（见第六节） |
| `registry.conflict` | 托管注册时与本地配置冲突 |
| `module.rejected` | 某模块接入被拒绝（`{ 模块, 原因, 详情, 级别 }`） |
| `module.held` | 模块暂下线等待人工确认（`error`） |
| `module.updateAvailable` | 有新版本但自动更新关闭（`{ 模块, 旧版本, 新版本 }`） |
| `module.offline` | 状态查询失败，判为离线 |

### 4.4 心跳

发送 `{"type":"ping","id":"…","from":"my-tool"}` → 平台回 `pong`（`echo` 为 ping 的 id）。
建议 30 秒一次。

### 4.5 模块自身的上下线通知（可选）

模块可在连上 / 断开时主动告知平台（平台不强制，但能让双方状态更一致）：

```json
{ "type": "event", "from": "my-tool", "action": "module.startup", "params": { "name": "my-tool", "version": "0.1.0", "path": "…", "pid": 1234 } }
```

```json
{ "type": "event", "from": "my-tool", "action": "module.shutdown", "params": { "name": "my-tool", "version": "0.1.0" } }
```

### 4.6 查询平台状态

外部模块可以查询平台是否在线、版本多少、平台里有哪些模块：

| action | 返回 |
|---|---|
| `nigane.platform.info` | `{ 在线, 平台, 版本, 协议, 启动时间, 运行秒数, 模块数 }` |
| `nigane.modules.names` | 当前在线模块名数组 |
| `nigane.registry.details` | 所有模块的详细运行时状态 |
| `nigane.registry.config.list` | 配置列表（含版本 / 自动更新 / 状态灯 / 待确认） |
| `nigane.registry.query` | 主动向某模块发 `module.query`（`{ name }`） |
| `nigane.registry.apply` | 手动确认采纳新信息（`{ name }`） |
| `nigane.registry.remove` | 取消注册（`{ name }`） |

SDK 已封装为 `await client.platform_info()` / `await client.list_modules()`。

### 4.7 配置声明与双向推送（让平台给你生成配置页）

你**不需要写任何前端代码**就能获得配置界面：握手时上报 `配置声明`，
平台据此渲染表单；用户改配置后平台推送给你，你自己热重载。

#### 握手时上报

```json
{
  "type": "hello",
  "params": {
    "name": "my-tool",
    "配置声明": {
      "说明": "我的工具配置",
      "字段": [
        { "键": "host", "标题": "服务地址", "类型": "string", "提示": "http://127.0.0.1:9000" },
        { "键": "enabled", "标题": "启用", "类型": "boolean", "默认值": true },
        { "键": "mode", "标题": "模式", "类型": "select",
          "选项": ["fast", { "值": "quality", "标题": "高质量" }] },
        { "键": "token", "标题": "密钥", "类型": "secret", "凭据": true }
      ]
    }
  }
}
```

**字段类型**：`string` / `text` / `number` / `boolean` / `select` / `path` / `secret` / `array`。

- `键` 支持点号表示嵌套：`engines.voxcpm.url` ↔ 配置里的 `{ engines: { voxcpm: { url } } }`
- `number` 可加 `最小` / `最大` / `步进`
- `select` 的 `选项` 可写字符串或 `{ 值, 标题 }`
- `array` 需声明 `数组: { 元素: "string" }` 或 `{ 元素: "object", 列: [...] }`
- **`凭据: true`**：值会被写进 `kugua.config.local.json`（不进版本库），
  查询表单时**只返回「已设置」标记，不返回明文**
- `生效`（可选）：`立即`（默认）/ `重启模块` / `重启平台`，仅用于界面提示

#### 接收配置推送

平台会在三个时机向你推 `module.config` 事件：

| 来源 | 时机 |
|---|---|
| `初始化` | 你每次上线（因此**不必自己读配置文件**） |
| `用户` | 用户在平台 UI 改了配置 |
| `模块` | 其他模块改了共享配置（少见） |

载荷：

```json
{
  "模块": "my-tool",
  "配置": { "host": "http://127.0.0.1:9000", "enabled": true },
  "来源": "用户",
  "变更": ["host"]
}
```

`配置` 是**合并后的完整配置**（主配置 + 本地覆盖层），你不用管两层文件。

#### 主动上报配置变更（可选）

模块自己发现新配置（例如扫描到可用模型列表）时可以反向写回：

```json
{ "type": "request", "action": "nigane.moduleConfig.report",
  "params": { "变更": { "models": ["a", "b"] } } }
```

平台写盘成功后，会把结果**广播给所有模块**（含你自己）。
你还可以随请求附带 `声明` 字段来更新自己的字段声明（例如动态音色列表）。

#### 平台侧接口

| 动作 | 说明 |
|---|---|
| `nigane.moduleConfig.declarations` | 全部模块的配置声明 |
| `nigane.moduleConfig.get` | `{name}` → 表单模型（凭据已脱敏） |
| `nigane.moduleConfig.set` | `{name, 变更}` → 写盘并推送 |
| `nigane.moduleConfig.report` | `{变更, 声明?}` → 模块主动上报 |

### 4.8 自定义 UI 页（声明式表单不够用时）

如果配置页需要声明式表单表达不了的交互（音色试听、模型下载进度、实时预览），
可以自带一个 HTML 页面，平台会在顶栏生成一个 iframe 标签页。

握手时上报 `ui`：

```json
{
  "type": "hello",
  "params": {
    "name": "my-tool",
    "ui": { "title": "我的工具", "entry": "ui/index.html" }
  }
}
```

- `entry` 是**相对模块入口文件所在目录**的路径。例如入口是
  `packages/modules/tts/dist/index.js`，那 `ui/index.html` 就解析为
  `packages/modules/tts/dist/ui/index.html`。
- 页面通过 `GET /module-ui/<模块名>/<路径>` 提供，防目录穿越。
- 页面内引入 `/plugin-sdk.js` 即得 `window.kugua`（仅 HTTP，不建 WebSocket）：

```html
<script src="/plugin-sdk.js"></script>
<script>
  const r = await window.kugua.request("my-tool", "my.action", { ... });
</script>
```

#### 凭据字段（`凭据: true`）

写在字段上表示「这是敏感值」：

```json
{ "键": "apiKey", "标题": "密钥", "类型": "secret", "凭据": true }
```

平台会把它写进 `kugua.config.local.json`（已 gitignore），不进版本库；
表单也只回 `已设置: true`，不回明文。

**对象数组的列上也可以标记**，这很重要：

```json
{
  "键": "providers", "标题": "提供方", "类型": "array",
  "数组": { "元素": "object", "列": [
    { "键": "name", "标题": "名称", "类型": "string" },
    { "键": "apiKey", "标题": "密钥", "类型": "secret", "凭据": true }
  ]}
}
```

不标记的话，`providers[0].apiKey` 会跟着整张表写进公开配置文件。

两条约定（模块侧需要配合）：

1. **第一列是主键**。凭据层会存成 `[{ apiKey, name }]`，
   靠主键把密钥对回正确的行。所以第一列请用一个稳定的标识（名称、id）。
2. **读配置时必须合并两层**。平台把凭据存在 local 文件里，
   你自己读 `kugua.config.json` 是读不到密钥的。参考 AI 模块的
   `合并提供方()`：按主键逐行把 `apiKey` 补回公开层。

**什么时候用哪个**：

| 场景 | 用声明式表单（4.5） | 用自定义页（本节） |
|---|---|---|
| 开关、地址、路径、下拉 | ✅ | 过度设计 |
| 列表增删（音色、模型） | ✅ | 可以 |
| 试听、进度条、实时预览 | ❌ 表达不了 | ✅ |
| 复杂表格编辑 | ❌ | ✅ |

两者可以**并存**：长期配置走声明式表单，临时操作/试听走自定义页。
tts 模块就是这么做的。

## 五、能力声明

`capabilityDefs` 是你这个模块「能做什么」的清单，决定平台如何暴露你：

```json
{
  "name": "my-tool",
  "version": "0.1.0",
  "capabilityDefs": [
    {
      "名称": "my-tool.echo",
      "模块": "my-tool",
      "动作": "my-tool.echo",
      "标题": "回声",
      "说明": "把输入原样返回",
      "中文指令": ["回声"],
      "参数": { "type": "object", "properties": { "text": { "type": "string" } } },
      "暴露": { "指令": true, "GUI": true }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `名称` | 全局唯一，建议 `模块.动作` |
| `模块` | 提供者模块名（你） |
| `动作` | 苦音 `action`；缺省等于 `名称` |
| `标题` / `说明` | 人类可读文案 |
| `中文指令` | 中文别名，命中即调用；**出现在指令面板 / 可被 AI 路由** |
| `参数` | 参数 JSON Schema（object） |
| `返回` | 返回 JSON Schema（可选） |
| `危险` | 危险能力，默认不对外暴露 |
| `长任务` | 走 Job 语义（进度、取消） |
| `暴露` | 各入口开关：`指令` / `GUI` / `HTTP` 等 |

**你不需要手写能力名列表**：省略 `capabilities` 时，平台会从
`capabilityDefs` 的 `动作 ?? 名称` 加上你实际注册的处理器自动派生。

## 六、生命周期（重要）

平台区分两类外部程序，**退出行为完全不同**：

### 6.1 平台托管的模块（配置在 `kugua.config.json` 的 `modules[]`）

平台**负责其生死**：
- 启动时由主控 `spawn`
- 崩溃按策略重启
- **平台退出 / 重启时同步关闭**（先 `SIGTERM`，2 秒未退则强制 kill）

### 6.2 运行中接入的外部程序（本协议的主要场景）

平台**不负责其生死**，只做通知：
- 平台退出时广播 `system.shutdown`：

```json
{ "type": "event", "from": "kugua-main", "action": "system.shutdown", "params": { "time": 1760000000 } }
```

- **收到后由你自己决定**是否退出。你可以：
  - 直接退出；
  - 继续运行（下次平台起来再重连）；
  - 做收尾工作后再退出。
- 平台不会对你的进程发送任何信号，也不会强杀。

### 6.3 断开与重连

- 你的连接断开 → 平台立刻移除你的能力，广播 `capability.changed`，
  UI 自动刷新，指令面板不再显示你的指令。
- 重连后重新 `hello` 即恢复。**同名顶号**处理见第三节。
- 建议外部程序实现**指数退避重连**（1s → 2s → 4s → … 上限 30s）。

## 七、最小可运行示例

仓库提供了两种语言的可运行示例：

### Python（推荐，带 SDK）

`sdk/` 目录下是完整的**外部模块接入 SDK**：

| 文件 | 说明 |
|---|---|
| `sdk/README.md` | 接入指南（快速上手、四种交互方式、能力声明、生命周期、FAQ） |
| `sdk/python/nigane.py` | **Python SDK**（单文件，可整份复制到你自己的项目） |
| `sdk/python/example.py` | Python 完整示例 |

```bash
pip install websockets
cd sdk/python
python example.py
```

最小接入代码只有 10 行：

```python
import asyncio
from nigane import NiganeClient, capability

client = NiganeClient(name="my-tool", capabilities=[
    capability("my-tool.echo", "my-tool", commands=["echo", "回声"]),
])
client.register("my-tool.echo", lambda p, m: {"text": p.get("text", "")})
asyncio.run(client.run())
```

需要下次跟随平台一起启动时，加上托管参数（详见 3.1 与 `sdk/README.md`）：

```python
client = NiganeClient(
    name="my-tool",
    managed=True,
    managed_entry=sys.executable,
    managed_args=[os.path.abspath(__file__), "--hosted"],
)
```

### Node.js（裸协议，不依赖任何库）

`examples/external-module/run.mjs` 是一个**刻意不依赖本仓库任何包**的实现，
只用 Node 内置能力 + 裸 WebSocket，用来证明协议可被第三方复刻：

```bash
node examples/external-module/run.mjs
```

它演示了：连接 → 握手 → 声明能力（`回声` 指令）→ 被平台调用 → 响应 →
订阅 `system.shutdown` 并在收到后自行退出。

## 八、非 Node 语言实现清单

用任何语言复刻时，只需要：

1. 一个 WebSocket 客户端库；
2. JSON 序列化；
3. UUID 生成（或任意唯一字符串）；
4. 维护「发出请求的 `id` → 等待中的回调」映射，靠 `echo` 配对；
5. 维护「收到的 `action` → 处理器」映射；
6. 握手后发送 `hello`，处理 `hello_ack`；
7. 订阅 `system.shutdown`，按 6.2 自行决定退出。

无二进制帧、无压缩、无自定义分帧——只有 JSON over WebSocket。
