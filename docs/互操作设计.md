# 互操作设计（MCP 与跨语言模块）

> 本文定义苦瓜工作室如何"对外暴露能力"与"接入外部项目"。
> 统一使用 MCP（Model Context Protocol，JSON-RPC 2.0）作为互操作协议。
> 能力声明见《架构设计.md》第四节；协议信封见《开发细则.md》。

## 一、为什么要 MCP

需求是"便于插拔及外联其他的小项目"。若为每个外部项目手写适配器，成本高且易腐。
MCP 已成为事实标准的"工具/资源/提示"暴露协议，且是纯 JSON-RPC：

- 外部项目只要实现 MCP server，就能被本平台当作模块使用（无需写 TS 适配）；
- 本平台实现 MCP server 后，任意 MCP 客户端（编辑器、Agent、脚本）都能调用本平台能力；
- 一份能力声明同时生成 MCP `tools`，无需重复维护。

## 二、角色

| 角色 | 包 | 作用 |
|---|---|---|
| MCP Server | `@kugua/mcp`（server） | 把能力注册表暴露为 tools/resources/prompts |
| MCP Client | `@kugua/mcp`（client） | 连接外部 MCP server，导入其工具为本平台能力 |
| 映射 | `@kugua/capability` | 能力声明 ↔ MCP Schema 双向转换 |

## 三、暴露映射（Server）

| 本平台 | MCP | 说明 |
|---|---|---|
| 能力声明（`暴露.MCP=true`） | `tools` | `inputSchema` 直接使用能力的 JSON Schema |
| MKG 节点 | `resources` | URI 形如 `mkg://node/<id>`、`mkg://search?tags=…` |
| 位置与保存视图 | `resources/templates` | 参数化资源 |
| DScript 模板/提示词 | `prompts` | 可选 |

### 3.1 传输

- **默认 stdio**：与"模块即进程"模型一致，天然隔离，不监听网络；
- **可选 Streamable HTTP**：仅在显式配置时开启，绑定 `127.0.0.1`。

### 3.2 暴露策略

- `危险=true` 或含 `exec` / `filesystem:write` 的能力默认**不暴露**；
- 可在配置中列出白名单显式放开；
- 每次 `tools/call` 记录审计（来源、能力、参数摘要、结果、耗时）。

## 四、接入映射（Client）

外部 MCP server 的 `tools` 被导入为本地能力声明：

```
MCP tool { name, description, inputSchema }
      ↓
能力声明 { 名称: "ext.<server>.<tool>", 模块: "mcp-client", 动作: "mcp.call", ... }
```

- 支持 stdio 启动外部命令，或连接 HTTP 端点；
- 工具名加前缀避免与内置能力冲突；
- 权限按 server 配置统一授予（如某外部 server 只有 `network`）；
- 外部 server 的失败/超时按普通能力调用的错误处理。

## 五、跨语言模块契约（脚本模块）

除 MCP 外，允许"轻量脚本模块"直接接入，约定：

```
module/
  kugua-module.json      # manifest：name/version/runtime/entry/permissions/capabilities
  main.py                # 或任意可执行文件
```

- 宿主以 stdio 启动 `entry`，双方以**换行分隔的 JSON**（JSON Lines）通信；
- 方法集与 MCP 对齐：`initialize` / `tools/list` / `tools/call`（可视为"本地 MCP server"）；
- 优点：Python 脚本、爬虫、安全测试工具无需引入 Node SDK 即可成为一等模块；
- manifest 的 `permissions` 参与权限取交集校验。

> 结论：**脚本模块 = 由宿主直接托管的本地 MCP server**。无需另造协议。

## 七、落地现状（已实现）

### 7.1 暴露（Server）

- **WebUI HTTP**：`POST http://127.0.0.1:24600/mcp`（JSON-RPC，Streamable HTTP）。
- **独立 stdio**：`node packages/mcp/dist/bin.js`（供只支持 stdio 的客户端作为命令配置）。
- 工具来源：主控能力注册表中 `暴露.MCP=true` 的能力；GET 列表每次请求实时拉取。
- 资源：`resources/list` 返回最近节点（`mkg://node/<id>`），`resources/read` 按 URI 读取。
- 危险能力默认不暴露；即使声明了 `暴露.MCP`，`危险=true` 且未开 `允许危险` 也会被过滤。

### 7.2 接入（Client）

模块 `@kugua/module-mcp-client` 读取两类来源并导入工具：

1. `kugua.config.json` 的 `mcp.servers[]`：`{ name, command, args, env, cwd, prefix, timeoutMs }`；
2. 脚本模块：`mcp.scriptsDir`（默认 `scripts/modules`）下每个子目录的 `kugua-module.json`。

每个外部工具注册为能力 `前缀.工具名`（动作同名），可直接 `capability.call` 或（若声明）通过中文指令调用。
内置 `mcp-client.providers` 可查询已接入的提供者与工具。

### 7.3 脚本模块清单（kugua-module.json）

```jsonc
{
  "name": "demo-echo",
  "version": "0.1.0",
  "command": "node",      // 或 python 等
  "args": ["main.mjs"],   // 相对脚本目录
  "prefix": "demo",
  "env": {},
  "timeoutMs": 30000
}
```

脚本进程按 JSON Lines 与宿主交换 JSON-RPC（MCP），至少实现 `initialize` / `tools/list` / `tools/call`。
示例见 `scripts/modules/demo-echo/`。

## 八、安全

- MCP server 默认 stdio，不开网络端口；
- HTTP 模式必须绑定回环并建议启用令牌；
- 危险能力白名单 + 审计；
- 外部 MCP server 视为不可信：限超时、限输出大小、限工作目录。
