# 苦瓜工作室 架构设计

> 本文是本项目的顶层蓝图，定义"苦瓜工作室"是什么、由哪些层组成、各层之间如何协作。
> 具体编码规范、协议字段、目录约定见《开发细则.md》；知识库见《知识库设计.md》；对外互操作见《互操作设计.md》；
> 分阶段施工任务见《改造清单.md》。

## 一、定位

苦瓜工作室（KuguaStudio，KS）是一个**纯本地的个人自动化工作台**：

- 常驻宿主后台，随系统启动；
- 以**可插拔模块**承载功能（图片/GIF 处理、文本工具、历法、脚本任务、爬虫、系统任务……）；
- 各模块通过**统一信息总线**通信与协同；
- 提供**中文指令**与**图形界面**两种入口，且同一功能自动同时具备"指令 / 界面 / 定时 / 开机 / 外部接口"多种使用方式；
- 内置**本地知识库（MKG）**，以标签图 + 全文检索替代一部分 Windows 资源管理器，统一管理图片、多媒体、文本段与学术资料；
- 能方便地执行与调度**临时脚本任务**（Python / 爬虫 / 安全测试等），并**外联其他小项目**。

> 注意：本项目**不是** AI 应用平台。AI 只是一项可选的外部能力（通过统一网关调用），
> 核心价值在于"本地功能可插拔 + 可调度 + 可检索 + 可互操作"。

## 二、设计原则

1. **本地优先**：默认不依赖任何云服务；网络功能显式声明、可关闭。
2. **文件系统为真源**：知识库只是索引与标签层，不搬迁、不破坏原始文件；标签可随文件携带（侧车）。
3. **进程隔离**：每个模块是独立进程，崩溃不影响主控与其他模块。
4. **一处声明，多处暴露**：一个功能只在"能力注册表"声明一次，自动派生全部入口（见第四节）。
5. **跨语言**：模块可以用 TypeScript、Python 或任意可执行文件实现，只要能讲统一契约。
6. **最小依赖**：优先 Node 内置能力与单文件 SQLite；不引入需要长期运维的中间件。
7. **权限显式化**：任何涉及文件写、网络、执行外部程序的模块必须在能力声明里写明权限，危险能力默认不对外暴露。
8. **可演进而非推倒**：总线协议保持向后兼容；新增能力通过扩展而非破坏既有语义。

## 四、能力注册表（核心）

### 4.1 为什么需要它

现状问题：同一功能在指令、GUI、调度、开机、外部调用里各写一遍，改一处漏三处。
能力注册表把"功能"变成一等公民：**声明一次，五处自动可用**。

### 4.2 能力声明

```jsonc
{
  "名称": "image.gifUnzip",          // 全局唯一，建议 `模块.动作`
  "模块": "image",                    // 提供者模块名
  "动作": "image.gifUnzip",           // 苦音 action，缺省等于名称
  "标题": "GIF 拆帧",
  "说明": "把 GIF 拆成多张图片返回",
  "中文指令": ["gif拆帧", "拆gif"],
  "参数": {                           // JSON Schema（object）
    "type": "object",
    "properties": { "base64": { "type": "string" } },
    "required": ["base64"]
  },
  "权限": ["filesystem:read"],        // 见 4.5
  "危险": false,                       // 危险能力默认不暴露给 MCP
  "长任务": false,                     // true 走 Job 语义（第五节）
  "暴露": { "指令": true, "GUI": true, "定时": true, "MCP": true }
}
```

### 4.3 五种入口的派生

| 入口 | 来源 | 行为 |
|---|---|---|
| 中文指令 | `中文指令[]` + `参数` | 解析文本 → 参数 → 调用能力 |
| GUI | `标题/说明/参数` | WebUI 命令面板项 / 按钮 / 表单 |
| 定时任务 | `暴露.定时` | scheduler 的候选动作 |
| 开机任务 | `暴露.定时` + 位置=启动 | 登录后自动执行一次 |
| 外部接口 | `暴露.MCP` | MCP `tools`，JSON Schema 直接复用 |

### 4.4 注册与调用

- 模块在握手（`hello`）时携带 `capabilityDefs`（能力声明数组）与 `capabilities`（能力名列表）；主控汇总为全局注册表。
  - **能力名无需手写**：`NiganeClient` 在握手时自动合并「能力声明（取 `动作 ?? 名称`）
    + 已注册的请求动作（`onRequest`）」作为 `capabilities`（除非调用方显式传入）。
  - 未提供显式声明时，主控由 `capabilities` 名称自动合成基础能力（名称即动作、GUI 可见）；
  - 与模块同名的自标识（如 `capabilities: ["webui"]`）不注册为能力。
- 因此模块只需**声明能力（富元数据）+ 注册处理器**两件事，不再维护第三份能力名清单，
  也不会出现「清单与实际注册动作漂移」。
- 运行时变更（上下线/热插拔）通过事件 `capability.changed` 广播，各入口刷新。
- 主控内置动作：`capability.list` / `capability.get` / `capability.call` / `capability.command`。
- 统一调用：`registry.invoke(名称, 参数)` → 主控经 `NiganeServer.request` 路由到 `模块.动作`。
- 中文指令调用约：`capability.command` 命中后向模块传入 `{ 参数文本, 原文 }`：
  - `参数文本` 为命中指令后的剩余文本；`原文` 为完整指令，便于如 `r3d6` 这类“参数含在指令内”的命令。

### 4.5 权限模型

| 权限 | 含义 |
|---|---|
| `filesystem:read` | 读取指定位置的文件 |
| `filesystem:write` | 写入/删除文件 |
| `network` | 发起网络请求 |
| `exec` | 执行外部程序/脚本 |
| `device` | 访问设备（音频/摄像头等） |
| `clipboard` | 读写剪贴板 |

规则：
- 权限在能力声明与模块 manifest 两处声明，取交集生效；
- `危险` 或含 `exec`/`filesystem:write` 的能力默认不暴露给 MCP；
- 所有调用写入审计日志（来源、能力、参数摘要、结果、耗时）。

## 五、长任务（Job）

短请求用 `request/response`，广播用 `event`；**长任务不新增信封类型**，而是一组约定动作，
以保持协议兼容：

| 动作 | 语义 |
|---|---|
| `job.start` | 启动任务，返回 `{ jobId }`；参数含 `能力名`、`参数`、`工作目录`、`超时`、`环境变量` |
| `job.status` | 查询状态：`queued/running/done/failed/cancelled` + 进度 |
| `job.cancel` | 终止任务进程树 |
| `job.list` | 列出当前与历史任务 |
| `job.log`（event） | 流式推送 stdout/stderr 行 |
| `job.done`（event） | 完成事件，含退出码与产物路径 |

运行时要求：
- 独立进程、独立工作目录、显式环境变量；
- 超时与资源上限、可取消（Windows 终止进程树）；
- 历史落 SQLite（作业表），供 GUI 查看与重跑；
- 典型用途：Python 脚本、爬虫、安全测试、批处理。

## 六、模块与插件

### 6.1 三种模块形态

| 形态 | 实现 | 接入方式 |
|---|---|---|
| 内置模块 | TypeScript，`@kugua/*` 包 | 引用 SDK，作为 Nigane 客户端 |
| 脚本模块 | Python（或任意语言） | manifest + JSON-RPC over stdio |
| 外部项目 | 任意提供 MCP server 的程序 | 由 `@kugua/mcp` 客户端导入为能力 |

### 6.2 模块 manifest（`package.json` 的 `kugua` 字段）

每个模块包的 `package.json` 内用 `kugua` 字段声明其模块元信息（**单一事实来源**）：

```json
{
  "name": "@kugua/module-echo",
  "kugua": {
    "module": true,
    "type": "process",
    "entry": "dist/index.js",
    "autoStart": true,
    "description": "echo 示例模块（回声）"
  }
}
```

- `name` 默认取包目录名；`entry` 默认 `dist/index.js`；`type` 默认 `process`。
- `library` 类型用 `file` 指向产物（如 `bin/math.dll`），不随主控启动。
- `scripts/sync-modules.mjs` 扫描所有 workspace 包，据此自动生成 `kugua.config.json` 的 `modules[]`
  与根 `package.json` 中每个模块的 `start` 脚本；根 `build` 亦改为
  `npm run build --workspaces --if-present`（npm 按工作区依赖拓扑排序）。
- 因此**新增/删除模块只需建/删包并写 `kugua` 字段**，配置、启动脚本、构建顺序自动跟随；
  `npm run check:modules` 供 CI 校验一致性。

### 6.3 生命周期

`on_load` → `on_enable` → （运行）→ `on_disable` → `on_unload`；
运行时支持扫描、热重载、启用/停用、卸载。现有 `@kugua/plugin-sdk` 复用，增加能力声明。

#### 运行时动态检测（模块）

主控不再只在启动时读一次配置：

- **`nigane.registry.reload`**：重读 `kugua.config.json`，与当前描述表做差集：
  新增模块写入描述表（process + autoStart 则拉起）、移除模块从描述表移除（先停其进程）、
  入口变化的模块重启以加载新代码；返回变更摘要并广播 `registry.changed`。
- **配置热检测**：每 5 秒比对配置文件指纹，变更后自动触发 `reload`，无需手动操作。

#### 运行时动态检测（插件）

`plugins` 模块监听插件目录（防抖）+ 15 秒定时兜底：
投放插件目录 → **自动发现并启用**；目录消失 → **自动卸载**；变更时广播 `plugins.changed`。
同时提供 `plugins.detect` 供手动触发；`install/update/reload/enable/disable/uninstall` 保持可用。

#### 单实例与端口冲突

- **全系统单例（强制）**：以**操作系统级锁文件**判定，由 `@kugua/paths` 的
  `抢占全局单例锁` / `读取单实例锁` / `全局单例锁路径` 提供。
  锁路径与 **cwd / 配置 / `KUGUA_DATA_DIR` 全部无关**：
  - Windows：`%LOCALAPPDATA%\KuguaStudio\studio.lock`
  - 其它：`$XDG_RUNTIME_DIR/kugua-studio/studio.lock`，回退 `~/.kugua-studio/studio.lock`
  - `KUGUA_GLOBAL_LOCK` 可显式覆盖（仅供测试隔离使用）

  因此**改端口、改配置、改数据目录、换目录启动都无法绕过**。
  用 `wx` 独占创建做**原子抢占**，两个进程同时启动也只有一个拿到锁；
  锁文件里记录持锁 pid，pid 已死或文件损坏视为陈旧锁自动接管；
  释放时校验 pid，只删自己的锁，绝不误删新实例的锁。
  发现已有实例时只提示并退出，**不发送任何信号、不结束任何进程**。
- **WebUI 与主控同属一个实例**：WebUI 先抢锁，再用 `KUGUA_LOCK_HELD=1`
  启动子主控；子主控校验锁确实存在且不属于自己后才跳过抢锁
  （避免环境变量被滥用绕过单例）。主控启动失败时 WebUI 一并退出并释放锁。
- **端口冲突 ≠ 已有实例**：端口可在配置中调整，也可能被其它程序占用。
  端口探测只用于报错——`启动失败：端口 <host>:<port> 已被其他程序占用，请修改 port`
  并以非 0 退出；**绝不把端口占用当作「已有 Studio 在运行」**。
  主控检查 `port`，WebUI 额外检查 `webui.port`。
- **退出钩子**：`process.on("exit")` 与优雅关闭都释放锁。
  被强杀（`TerminateProcess`）时不会触发钩子，但下次启动会因 pid 已死
  自动接管陈旧锁，不影响使用。
- **测试隔离**：`ui-gate.js` / `ui-check` 的隔离实例用
  `KUGUA_GLOBAL_LOCK=<临时目录>/studio.lock`，因此可与用户正在运行的 Studio 共存。
- **重启**：`POST /api/restart` 先关闭主控与全部模块，再 detached 重拉自身，
  旧进程释放锁后退出；设置页「平台运行」提供重启/退出按钮。

### 6.4 模块重写范式（阶段 1 落地）

后续功能模块统一按下式重写：**声明能力 + 处理函数**，不再各自实现入口与帮助文案。

```ts
import { NiganeClient } from "@kugua/nigane";
import type { 能力声明 } from "@kugua/capability";

// 1) 一处声明：指令 / GUI / 定时 / 外部接口均由注册表派生
const 能力清单: 能力声明[] = [
  {
    名称: "text.reverse",
    模块: "text",
    标题: "反转文本",
    说明: "将文本逐字反转",
    中文指令: ["反转"],
    参数: {
      type: "object",
      properties: { 文本: { type: "string", description: "待反转文本" } },
      required: ["文本"],
    },
    暴露: { 指令: true, GUI: true, 定时: false, MCP: false },
  },
];

// 2) 握手时上报能力声明；具体实现留在模块进程内
const 客户端 = new NiganeClient({
  name: "text",
  host, port, token,
  capabilities: 能力清单.map((c) => c.名称),
  // capabilityDefs: 能力清单   // 阶段 1 在 NiganeClient 选项中加入
});

客户端.onRequest("text.reverse", (参数) => {
  const { 文本 } = 参数 as { 文本: string };
  return [...文本].reverse().join("");
});

await 客户端.connect();
```

约定：
- 能力名与动作名使用英文 `模块.动作`；
- 参数一律用 JSON Schema 描述，便于 GUI 表单与 MCP inputSchema 复用；
- 需要文件/网络/执行权限的能力必须在 `权限` 中声明；
- 长任务（脚本/爬虫）声明 `长任务: true`，走 `job.*` 约定。

### 6.5 插件自带 UI 页

插件可在 manifest（`kugua-plugin.json`）中声明 `ui`，WebUI 会自动为其生成一个顶栏标签页：

```json
{ "ui": { "title": "示例页", "entry": "ui/index.html" } }
```

- **托管**：WebUI 服务提供 `GET /plugin-ui/<插件名>/<路径>`（默认取 `ui.entry`；防目录穿越），
  以及 `GET /api/plugin-pages` 返回带 UI 的插件列表。
- **调用能力**：插件页引入 `/plugin-sdk.js` 后即得 `window.kugua`
  （`request` / `broadcast` / `getFileUrl` / `readMediaFile` / `dialog` 等，仅 HTTP、不建 WebSocket）。
- **隔离**：插件页在 iframe 中加载，与主界面隔离；示例见 `templates/plugin-template/ui/index.html`。

## 六·五、WebUI 前端结构

- **入口**：`packages/webui`（HTTP + WebSocket + 静态页）；浏览器通过 `kugua-shim.js` 注入
  与旧 Electron 一致的 `window.kugua`，渲染层直接复用。
- **桥接层（TS + ESM）**：`src/renderer/bridge.ts` 是 `window.kugua` 的**唯一类型与实现来源**
  （`苦瓜基础接口` / `苦瓜接口` + `请求()` + `创建基础接口()`）；
  `kugua-shim.ts`（主界面，含 WebSocket 日志/就绪/总线事件订阅与窗口控制占位）与 `plugin-sdk.ts`
  （插件页，仅 HTTP、无窗口控制）均由其派生；`01-types.ts` 的 `Window.kugua` 直接引用 `bridge` 类型。
- **前端刷新策略（事件驱动）**：主控广播的总线事件（`registry.changed` / `capability.changed` /
  `plugins.changed`）由 WebUI 服务端转发到浏览器（WS `{ type: "bus", action, params }`），
  前端经 `window.kugua.onBus()` 订阅并做 200ms 合并刷新（`09-init.ts`），**不再固定轮询**；
  仅保留一条 120 秒的最终一致兜底。避免空闲时持续产生总线收发日志。
- **图片编解码（TS + ESM）**：`src/renderer/media-codec.ts`（由原 `media-codec.cjs` UMD 脚本转为标准 ES 模块）
  提供 PNG/JPEG/GIF/WebP/BMP 元数据、EXIF 地理信息与 GIF 帧解码；由 `parts/03-preview.ts` 直接 import
  并随 index.js 打包（**不再单独引入脚本**），且因无 DOM 依赖而可直接用 vitest 单元测试
  （`packages/webui/test/media-codec.test.ts`）。
- **渲染层模块化（原生 ESM + esbuild）**：源码按功能拆为 `src/renderer/parts/NN-*.ts`，
  每个文件是独立的 **ES 模块**（显式 `import` / `export`），入口为 `parts/main.ts`（按序号导入各分区，
  保证副作用初始化顺序）。构建时用 **esbuild** 打包为单文件 IIFE（`dist/renderer/index.js`），
  `index.html` 无需改动；无需运行时依赖，产物零依赖。

  | 文件 | 职责 |
  | --- | --- |
  | `01-types.ts` | 共享类型 + `Window.kugua` 声明 |
  | `02-chat-core.ts` | 对话终端、消息渲染、指令提示 |
  | `03-preview.ts` | 图片预览弹窗（GIF/元数据/复制） |
  | `04-router.ts` | 命令路由器（自然语言 → 能力调用） + 指令前缀表（需参/写法推断） |
  | `05-format.ts` | 结果格式化 |
  | `06-shell.ts` | 侧边栏、通用确认框 |
  | `07-explorer.ts` | 知识库资源管理器（核心：列表/标签树/菜单/编辑器 + `init`） |
  | `07d-explorer-notes.ts` | 知识库·点子（已合并入统一资料库，仅保留编辑对话框与事件） |
  | `07e-explorer-materials.ts` | 知识库·素材（同上） |

  构建：`tsc -p tsconfig.renderer.json` 仅做类型检查（`module: ESNext` + `moduleResolution: Bundler`，`noEmit`），
  再由 `scripts/build-renderer.mjs`（esbuild）产出**三个 IIFE 产物**：`index.js`（主界面）、
  `kugua-shim.js`（桥接，必须早于 index.js 加载）、`plugin-sdk.js`（经 `/plugin-sdk.js` 给插件页）。
  约束：ESM 下**导入绑定不可写**，共享可变状态需在拥有模块内提供 setter（如
  `设置提示选中索引` / `设置图片缩放倍率`）或改为对象属性；`Window` 增强需写在 `declare global { ... }` 中。
  例外：命名空间成员（如 `Explorer.标签树` / `Explorer.选中内容`）是**对象属性**，跨模块可读可写，
  因此子模块与核心之间直接以 `Explorer.成员` 共享状态，无需 setter。
- **`init` 只做编排**：`Explorer.init()` 仅按序调用 `绑定搜索与视图事件` / `绑定智能视图与位置事件` /
  `绑定内容操作事件` / `绑定详情标签事件` / `绑定编辑器事件` / `绑定对话框事件` / `绑定页面切换事件` /
  `绑定容器交互事件`，随后加载数据并 `切换视图`；具体 DOM 绑定在各命名函数内。
- **页面/标签**：统一在 `视图映射` 注册（对话 / 知识库 / 作业 / 工具 / 插件 / 日志 / 设置），
  新增页面只需登记一条映射 + 一个按钮，入口一致且互不耦合。
- **对话页**：多对话/多项目（localStorage 持久化）。**指令面板**（`16-cmd-panel.ts`，聊天页左侧）
  从能力注册表（`capability.list`）+ 本地路由内置指令库 + **路由前缀表**（`04-router.ts` 的
  `指令前缀表` / `推断指令需参`）汇总，并随 `capability.changed` 刷新；
  **单击**免参指令直接调用、需参指令（如 `吃什么` / `谐音`）只把前缀填入输入框；
  **双击**设为互斥的**持续前缀（对话模式）**，此后每条输入自动拼接该前缀
  （`08-logs.ts` 发送前由 `应用持续前缀` 处理）。**最近使用**排最前
  （localStorage `kugua_recent_cmds_v1`）；可筛选、拖拽调宽、折叠。
- **随机汉字**：指令 `随机n*m`（对齐参考 C# `handleRandomString`）——**n = 列、m = 行**，
  如 `随机5*4` → 5 字一行共 4 行；行/列默认 1，总量 > 2500 时自适应截断。
- **消息就地编辑 / 回复版本**：回复统一收进用户气泡下的 `.msg-replies` 容器；
  每次执行生成一个版本，历史存 `data-versions`（随对话 `innerHTML` 持久化）。
  点击自己发的消息可就地编辑（Enter 提交 / Esc 取消），重发**不新增 user 气泡**，
  结果作为新版本追加；多版本时容器左下角显示 `‹ n/N ›` 导航条可左右回切。
  为避免重发把整个历史发给 AI，编辑后重发只重跑该条指令（`处理输入重发`）。
- **回复栏图标**（模块名右侧同一行）：`▾ 折叠` / `↻ 刷新` / `☆ 收藏`。
  折叠只留模块名一行；刷新 = 重跑原指令作为新版本；
  收藏写入知识库——文本 → `mkg.note.create` 笔记，多媒体（`data:` 图片/音频）
  → `mkg.resource.saveBase64` 资源文件 + 笔记引用；
  标签 = 模块名 + 当前对话标题。已收藏显示左侧 ★ 与黄色强调条，再点取消。
- **输入路由**：**指令优先**——先走本地路由（`路由指令`），再走能力注册表（`capability.command`）；
  均未命中则提示「未识别的指令」，**不再兑底发给 AI**。AI 对话需显式前缀 `ai <内容>`（忽略大小写，
  兼容 `问AI` / `AI问答`），并委托带会话记忆的 `与AI对话`（按 `chatId` 保留上下文）。
- **日志页**：总线通信日志（前端）+ `nigane log.tail` 系统日志（含各模块/插件细节与报错）。
- **插件 UI**：插件 manifest 声明 `ui` 即自动生成标签页（iframe + `/plugin-sdk.js`）。
- **常驻**：Windows 系统托盘（`packages/webui/tray.ps1`，PowerShell NotifyIcon）：左键打开 WebUI，
  右键菜单「打开 / 开机启动（勾选，联动登录计划任务）/ 退出（终止服务进程树）」；
  带看门狗（服务退出则托盘自动退出）；`webui.tray=false` 关闭。
  实现约束：**不要用 `detached: true` 启动 powershell**（Windows 下会立即以 0 退出且不执行），
  改用 `windowsHide: true` + `unref()`，日志写入 `<数据目录>/tray.log`。
- **回归验证（已接入 npm 门禁）**：`npm run test:ui`（= webui 构建 + `scripts/ui-gate.mjs`）自动启服务、
  用无头 Chrome（CDP）断言：标签/视图齐全、切页无异常、系统日志渲染（`log.tail`）、新建对话（localStorage）、
  指令提示、主题切换、AI 模型列表，以及知识库的**写入回归**（新建点子/素材/记事列/卡片、新建片段并打开内置编辑器），
  要求全程控制台零错误；`npm test` = `test:unit` + `test:ui`，未装浏览器时自动跳过。
- **知识库信息架构（重构后）**：统一为三个子标签 `.ex-sub-tabs`：
  - **资料库**（`data-mode="files"`，`.ex-pane-files`）：**唯一的内容流**，点子/素材不再有独立页面，

    工作区**只保存 node 引用与位置**（`workspaces` / `workspace_items`），对应 `mkg.workspace.*`。

## 七、总线（Nigane）

- 传输：WebSocket 文本帧，主控监听 `127.0.0.1:24601`（可配置）。
- 拓扑：星型，主控是唯一服务端；模块间不直连。
- 消息：`hello / hello_ack / request / response / event / error / ping / pong`。
- 约定命名空间：`模块.动作`；能力动作即 `模块.动作`；作业动作 `job.*`。
- 协议演进只增加可选字段，不改变既有字段语义。详见《开发细则.md》。

## 八、知识库与资源管理

概要（详见《知识库设计.md》）：

- 文件系统为真源；SQLite 存索引、标签、关系、保存视图、位置；
- 标签持久化在**侧车文件**（`.mkg.json`）中，可随文件迁移；
- 检索：`LIKE` 升级为 **FTS5 全文索引** + 标签查询 + 保存的智能视图；
- 统一节点模型：文件 / 目录 / 笔记 / 素材 / 文本段 / 看板卡片；
- 支持导入去重（sha256）、回收站删除、按扩展名配置打开方式。

## 九、常驻、调度与开机

- **常驻**：主控注册为 Windows 服务（WinSW/NSSM）或"登录时"任务；子进程由主控守护并按需重启。
- **调度**：内置 cron（5/6 段）；额外提供 `启动/登录` 触发器，桥接 Windows 任务计划程序（`schtasks`）可选。
- **开机任务**：本质是"位置=启动"的调度任务，随主控启动执行一次。
- **日志**：内存环形缓冲 + 限流落盘；空闲时不产生周期性磁盘写。

## 十、安全

- 模块与能力两级权限声明，最小授权；
- `exec` 能力默认不暴露；脚本任务限定工作目录与目标 allowlist；
- 所有能力调用与作业执行审计；
- 总线仅监听本机回环地址；令牌可选启用；
- MCP server 默认 stdio，不监听网络；如需 HTTP 需显式开启并绑定回环。

## 十一、非目标（明确不做）

- 不做云服务/多租户/账号体系；
- 不把 AI 作为必须依赖（无 AI 时全部功能仍可用）；
- 不深挖脆弱的第三方平台（Telegram / B 站直播 / 贴吧爬虫 / VTubeStudio 等），仅保留可选桥接位；
- 不做"什么都塞进数据库"——原始文件永远由文件系统持有。

## 十二、路线（详见《改造清单.md》）

1. **地基**：能力注册表 + 目录/协议规范 + 清理历史包袱；
2. **知识库**：MKG 数据模型升级（FTS5 / 侧车 / 保存视图 / 位置）；
3. **入口**：中文指令解析统一走注册表；GUI 命令面板接注册表；
4. **互操作**：MCP server（暴露平台）→ MCP client（接入外部项目）；
5. **长任务**：脚本/爬虫/安全测试的 Job 运行时 + 审计；
6. **常驻**：服务化 + 开机任务 + 调度桥接；
7. **功能重写**：按新约定逐个重写功能模块（图片/文本/历法/…），去掉历史实现。
