# 语音合成设计（引擎无关抽象）

> 本文说明 KuguaStudio 的 TTS 架构、选型依据与扩展方式。
> 实现位于 `packages/modules/tts/`。

## 一、为什么重构

旧实现把「引擎」写死在流程里：主提供方 GPT-SoVITS，失败依次回退 sherpa-onnx → ChatTTS → Windows SAPI。
带来三个问题：

1. **换引擎要改多处代码**——处理器、配置、状态查询各写一份分支。
2. **音色概念不统一**——GPT-SoVITS 音色是「权重对」，sherpa 是「说话人编号」，ChatTTS 是「种子数字」，彼此无法互换。
3. **新模型接不进来**——2025–2026 年主流模型（VoxCPM、IndexTTS、CosyVoice）都是零样本克隆，
   与旧的「微调权重」范式完全不同，硬塞进原结构会让分支爆炸。

重构后上层只认一套接口，引擎成为可插拔实现。

## 二、分层设计

引擎按**用途**分三层，调度时按此顺序尝试：

| 分层 | 定位 | 典型引擎 | 显存 | 延迟 |
|---|---|---|---|---|
| `fast` | 实时对话，占用少、输出快 | VoxCPM1.5（0.6B） | ~6 GB | RTF≈0.15 |
| `quality` | 有声书批处理，拟真、可调情绪 | IndexTTS-2.5（1.5B） | 8–12 GB | 较慢，可批处理 |
| `fallback` | 显存被占满时的兜底 | sherpa-onnx（纯 CPU）、Windows SAPI | 0 | 快但音质一般 |

调度规则：

1. **显式指定 `engine`** → 只试这个，失败直接报错（不静默换引擎，避免产出与预期不符）。
2. **未指定** → 配置里的 `defaultEngine` 优先，其后按 `fast` → `quality` → `fallback` 依次尝试，第一个成功即返回。
3. **未配置的引擎**（`fast` / `quality`）跳过，避免误连默认端口导致长时间超时。
4. **未配置的 `fallback` 引擎仍然参与**——它们的意义就是「别的都不行时还能出声」，
   且不依赖外部服务地址（sherpa 查本地 exe、SAPI 查系统语音包），未配置也能安全尝试。
   `enabled: false` 仍然一律排除。

## 三、选型依据（2025–2026）

以 Seed-TTS Eval 中文集实测为准（CER 越低越好，SS 越高越像，人类基准 CER 1.26 / SS 75.5）：

| 模型 | 规模 | 中文 CER↓ | 相似度 SS↑ | 情绪控制 | 显存 |
|---|---|---|---|---|---|
| **IndexTTS-2.5** | 1.5B | 1.03 | 76.5 | **5 种方式** | 8–12 GB |
| VoxCPM（0.5B） | 0.5B | 0.93 | 77.2 | 弱 | ~5 GB |
| **VoxCPM1.5** | 0.6B | ~1.0 | ~77 | 文字描述 | **~6 GB** |
| VoxCPM2 | 2B | — | — | 文字描述 | ~8 GB |
| Fun-CosyVoice3 | 0.5B | 1.21 | **78.0** | instruct 指令 | ~5 GB |
| F5-TTS | 0.3B | 1.52 | 74.1 | 无 | ~4 GB |

**第一类（低占用/快）选 VoxCPM1.5 的理由**：0.6B 却有 44.1kHz 输出（0.5B 老版只有 16kHz），
RTF 0.15 比实时快 6 倍，支持 SFT/LoRA 微调；比 VoxCPM2（2B，RTF 0.30）轻一半、快一倍。

**第二类（高质量/可调情绪）选 IndexTTS-2.5 的理由**：情绪控制有 5 种互相独立的方式（见下节），
这是有声书场景的刚需——CosyVoice3 只有一句 `instruct` 描述，无法编程化批量控制；
另有 `duration_factor`（0.5x–2.0x）精确控时长，用来对齐章节节奏。

**CosyVoice3-0.5B 作为备选**：若显存不够跑 IndexTTS，它 0.5B 却有全表最高相似度 78.0，
且支持 18+ 中文方言，自带 FastAPI。

**全部为开放权重可商用**，VoxCPM 为 Apache-2.0。

## 四、音色抽象

零样本与微调两类范式共用 `音色` 结构，由各引擎自行取用自己认识的字段：

```ts
interface 音色 {
  id: string;              // 供 tts.speak 的 voice 参数引用
  name?: string;
  description?: string;    // 自然语言描述，便于 LLM 挑选
  refAudio?: string;       // 参考音频路径（零样本必需）
  refText?: string;        // 参考音频对应文本（提升保真度）
  refLang?: string;
  gptWeights?: string;     // 以下为微调类引擎专用
  sovitsWeights?: string;
  speakerId?: number;      // 多说话人模型编号
}
```

**零样本模型只需参考音频**，不必训练。这意味着旧的工作流可以简化：
手上已有的语音样本直接作为参考音频即可，不用再辛苦微调权重对。

配置里的路径可以写相对路径（如 `data/tts/voices/narrator.wav`），
由 `解析音色路径()` 按项目根解析，换机器不用改配置。

## 五、情绪控制

`情绪控制` 结构与 IndexTTS 的五种方式对应，**各引擎忽略自己不支持的字段**而不是报错，
这样同一份剧本可以换引擎渲染：

```ts
interface 情绪控制 {
  text?: string;        // 自然语言描述，如「低沉压抑地朗读」
  refAudio?: string;    // 情绪参考音频，迁移该音频的情绪
  intensity?: number;   // 强度 0~1
  vector?: number[];    // 8 维向量，可编程精确控制
}
```

映射到 IndexTTS 参数：

| 我们的字段 | IndexTTS 参数 | 说明 |
|---|---|---|
| `vector` | `emo_vector` | 顺序：高兴、愤怒、悲伤、恐惧、厌恶、忧郁、惊讶、平静 |
| `refAudio` + `intensity` | `emo_ref_path` + `emo_alpha` | 情绪参考音频优先于文字描述 |
| `text` | `emo_text` + `use_emo_text` | 独立控制剧本文字与情绪描述 |

音色与情绪**解耦**：可以用角色音色配任意情绪，这是做有声书的关键。

## 六、语速语义统一

**约定：`speed > 1` 表示更快**。各引擎内部自行换算：

| 引擎 | 参数 | 换算 |
|---|---|---|
| VoxCPM | `speed` | 直接用 |
| IndexTTS | `duration_factor` | **取倒数**（它是时长倍率） |
| GPT-SoVITS | `speed_factor` | 直接用 |
| sherpa-onnx | `vits-length-scale` | **取倒数**（它是拉伸系数，越大越慢） |
| Windows SAPI | `Rate`（-10~10） | 近似换算 `(speed-1)*10` |

## 七、配置

在 `kugua.config.json` 里加 `tts` 节：

```jsonc
"tts": {
  "defaultEngine": "voxcpm",
  "engines": {
    "voxcpm": {
      "enabled": true,
      "url": "http://127.0.0.1:9881",
      "defaultVoice": "narrator",
      "voices": [
        {
          "id": "narrator",
          "name": "旁白",
          "refAudio": "data/tts/voices/narrator.wav",
          "refText": "参考音频里说的那句话",
          "refLang": "zh"
        }
      ]
    },
    "indextts": {
      "enabled": true,
      "url": "http://127.0.0.1:9882",
      "defaultVoice": "hero",
      "voices": [{ "id": "hero", "refAudio": "data/tts/voices/hero.wav", "refText": "我是主角" }]
    }
  }
}
```

支持的字段：

| 字段 | 说明 |
|---|---|
| `enabled` | `false` 时该引擎在调度中被跳过 |
| `url` | 服务地址（HTTP 类引擎） |
| `root` | 模型目录 / 可执行文件路径（本地类引擎，如 sherpa） |
| `model` | 模型名或标识 |
| `voices` | 音色表 |
| `defaultVoice` | 该引擎的默认音色 id |
| `timeoutMs` | 请求超时，缺省按分层取值（fast 60s / quality 180s / fallback 60s） |

**两层合并**：`kugua.config.local.json` 覆盖 `kugua.config.json`，空串视为未设置
（与 `ai.openwebui` 同一套策略）。凭据类内容放 local，已 `.gitignore`。

**旧配置自动迁移**：`迁移旧配置()` 把 `gptSovits` / `chatttsUrl` / `sherpaRoot` / `sherpaModel` / 顶层 `provider`
搬到新结构，且**只补不覆盖**（目标键已存在就保留用户现值）。音色的旧字段名
（`refAudioPath` / `promptText` / `promptLang` / `sid`）也会被归一。

## 八、能力接口

| 能力 | 说明 |
|---|---|
| `tts.speak` | 合成。支持 `text` / `engine` / `voice` / `speed` / `format` / `lang` / `seed` / `temperature` / `emotion` / `输出路径` |
| `tts.status` | 各引擎的配置与可用性（含能力声明） |
| `tts.voices` | 列出各引擎已知音色 |

`tts.speak` 返回：

```jsonc
{
  "base64": "…",            // 或用 输出路径 时改为 { 输出路径 }
  "engine": "indextts",     // 实际使用的引擎
  "voice": "hero",
  "format": "wav",
  "sampleRate": null,
  "elapsedMs": 1234
}
```

**实际引擎与格式都会如实返回**——请求的格式引擎不支持时会回落（优先 mp3/ogg 便于传输，其次 wav），
调用方据此判断，不要假设返回的一定是请求的格式。

## 九、探活

`可用()` 只做**轻量探测**，不加载模型权重（那要几十秒且吃显存）：

- HTTP 类引擎：TCP 连接测试（`端口可用`），不发 HTTP 请求。
  原因：部分服务（GPT-SoVITS 加载模型期间、vLLM 冷启动）会把请求挂住很久，探活反而拖慢状态查询。
- sherpa：检查可执行文件存在。
- SAPI：检查平台是 Windows。

服务「在监听」不等于「功能正常」，真正的问题交给合成调用去发现并报错。

## 十、扩展新引擎

以接入 CosyVoice3 为例，三步：

1. 在 `src/engines/` 写实现：

```ts
export class CosyVoice引擎 implements 语音引擎 {
  readonly name = "cosyvoice";
  readonly 能力: 引擎能力 = {
    tier: "quality",
    formats: ["wav"],
    zeroShot: true,
    finetune: false,
    emotion: { text: true, refAudio: false, vector: false },
    streaming: true,
    batch: true,
    vramGb: 5,
  };
  async 可用() { /* 轻量探测 */ }
  async 音色列表() { /* 读配置 */ }
  async 合成(请求: 合成请求) { /* 组装请求、发 HTTP、返回音频 */ }
}
```

2. 在 `src/engines/index.ts` 的 `登记内置引擎()` 里 `注册引擎(new CosyVoice引擎())`。
3. 在 `kugua.config.json` 的 `tts.engines.cosyvoice` 加配置。

**上层代码无需改动。** 也可以从外部 `注册引擎()`，便于第三方模块注入自定义引擎。

## 十一、引擎实现要点

### VoxCPM

走官方 **OpenAI 兼容**端点 `POST /v1/audio/speech`（vLLM-Omni / Nano-VLLM 也是同一形态）。

请求体先带扩展字段（`ref_audio` / `ref_text` / `instructions` / `seed` / `temperature`）；
若上游回 4xx（说明该部署不认扩展字段），**自动退化为纯标准 OpenAI 字段重试**。
这样一个引擎配置能同时兼容官方脚本与纯 OpenAI 实现。

### IndexTTS

`POST /tts`，两种响应形态都支持：直接回音频流，或回 JSON（含 `audio_path`）。
JSON 模式下读文件，若文件在系统临时目录则读完顺手删除，避免长期堆积。

### GPT-SoVITS（兼容保留）

旧接口 `api_v2.py`。音色 = 权重对 + 参考音频，切换音色需调
`/set_gpt_weights` 与 `/set_sovits_weights` 让服务端重载权重（实测 3–10 秒），
所以做了**「已加载就跳过」缓存**：同一音色连续合成只切换一次。
只配参考音频、没配权重的音色不触发切换，因此也能当「仅换参考音频」的临时音色用。

`media_type` 支持 wav / ogg / aac（aac 依赖服务端装 ffmpeg）。
注意 ogg/aac 容器的长度校验不能用 wav 的 44 字节阈值。

### sherpa-onnx / SAPI（纯 CPU 兜底）

sherpa 参数四件套 `--vits-model` / `--vits-tokens` / `--vits-lexicon` / `--vits-dict-dir`，
多说话人模型用 `--sid` 选编号；`--vits-length-scale` 越大越慢（需取倒数）。
SAPI 用 PowerShell `System.Speech`，语速映射到 `Rate`（-10~10）。

两者都写临时文件再读回，用完即删。SAPI 的语音包名可能含单引号，在 PowerShell 里需转义成两个单引号。
